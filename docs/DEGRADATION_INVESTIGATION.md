# 1seg 連続復調の後半劣化 — 調査記録

作成: 2026-09-27
対象: `~/oneseg-rs` / 札幌 NHK 総合 ch15 (485142857 Hz) / DS-DT308SV (RTL2832U)

---

## 1. 現象

200 秒の IQ キャプチャ (`/tmp/atk1.iq`, 405274624 bytes) を 1 本で連続復調すると、
RS 訂正不能ブロックの比率が **0.2% から 90.4% へ単調悪化する**。

```
blk      drop%
    200   0.20%
   2400   0.45%
   3500   1.51%
   6000  16.90%
  10000  49.00%
  20000  74.10%
  30000  82.80%
  53840  90.40%
```

TS 上の影響: I フレーム欠落が 16.016〜21.755 秒、TS ギャップ 18.952→21.088 秒 (2.135 秒)。
VLC で 20 秒付近から灰色破損。

---

## 2. 決定的な事実

### 2.1 IQ データは正常（物理層は完全正常）

| 入力 | 総blk | drop | 率 |
|---|---|---|---|
| 386MB 連続 1 本 | 53840 | 48660 | **90.4%** |
| 80MB を 4 分割して個別デコード | 5446 | 73 | 1.34% |
| **後半 200MB を別プロセスで** | — | — | **0.10%** |

同じ IQ の後半部分だけを新プロセスで処理すると 0.10%。同じ瞬間の同じ信号なので、
**チューナー・LO・温度・USB 電源・ADC クロックはすべて正常**。
劣化は「連続復調の内部状態に依存する」ことが確定。

### 2.2 入力品質は改善している（矛盾が核心）

```
h_avg : 424.79 → 414.83  (-2.34%)  相関 -0.9510
soft  :  0.7208 →  0.7453 (+3.40%)  相関 +0.9192
```

drop が 450 倍悪化する区間で等化器の出力信頼度 `soft` は **3.4% 上昇**している。
「信号品質が落ちて出力も落ちるExplanation」は成立しない。

### 2.3 ブロック位置の周期性は無い

`ISDBT_DROPPOS=1` の 256 bin ヒストグラム: 全残留値で 186〜194、完全にフラット。
mod 12 / 64 / 256 のいずれの周期も無い。

## 2.5 診断Distriban's訂正（2026-09-29、測定器が誤っていた）

**この節より前に書いた診断の多くは、壊れた指標を根拠にしている。先に読むこと。**

### (1) `rs_bit_errors` / `syndrome_weight` は上限 16 で頭打ち

`syndrome_weight()` は `syndromes()` が返す `[u8; NROOTS=16]` の
**非ゼロ要素の個数**を返す。これは「訂正を要したビット数」ではなく
「シンドロームが 0 でなかった個数」であり、**最大 16**。

実測（atk3.iq）: `bit/blk`（= 訂正bit/総blk）は **全期間 16.0 に張り付いた**。
`DEGRADATION_INVESTIGATION.md` §3 の #16「soft ��ランプ飽和」等は
この 16.0 という**頭打ちの値**を根拠に判断しており、結論を信用できない。
「RS は 100% / 訂正済み”字Gauge和「RS は全面崩壊」も同じ 16.0 になる。

**正しい指標**: `rs::decode_detail()` が返す `nerr`
（Berlekamp-Massey が推定した symbol 誤り数）と失敗理由 `rs::Fail`。
`rs_symbol_error_stats()` / `rs_fail_reasons()` で参照できる。

### (2) 成功ブロックのみ記録するカウンタは、劣化域で「正常」に見える

`dbg_depu_at_block` は `for cw in blocks`（=復号**成功**したブロック）の
内側でしか push されない。drop が 100% になると更新が**止まる**ので、
「depu は 0 のまま = 整列正常」という**反対の結論**に到達する（実測でこれに当たった）。

`ISDBT_DEPUALL=1` で `dbg_depu_all`（全ブロック記録）が有効。
実測: 全 15082 ブロックで `depu_pos % 4 == 0`、64 周期違反 0 件
→ **depunc 位相は実際に正常**。

### (3) `ISDBT_TRACE` は訂正不能ブロックで発火しない

ダンプループが成功ブロックのみ回すため、drop 100% の領域では何も出ない。
**遷移域**（drop 30〜60%、blk≒2500）を trace する。

### (4) `ndec` を二重に数えていた（2026-09-29 修正）

`stream.rs` に `self.ndec += 1;` が 2 連 있었った（2026-09-29 修正）。
これが `終了: 6384/3192 ブロック復号 (200.0%)` の正体。
表示バグであり復調への影響はない。

## 2.6 正しい指標で分かったこと（atk3.iq、総blk 15082）

| 総blk | drop% | **symerr/blk** | soft(ema) | h_avg | pilot位相 m4 | depu%4 |
|---|---|---|---|---|---|---|
| 768 | 2.2 | 2.86 | 0.722 | 419.2 | 一致 | 0 |
| 2196 | 3.1 | 3.66 | 0.722 | 418.5 | 一致 | 0 |
| 2910 | 7.4 | 4.29 | 0.725 | 417.4 | 一致 | 0 |
| 5765 | 44.6 | 6.01 | 0.735 | 412.6 | 一致 | 0 |
| 15082 | 78.8 | **7.24**（差分 8.00） | 0.774 | 403.0 | 一致 | 0 |

**決定的な事実**:

1. **`symerr/blk` が 2.7 → 8.00 に単調上昇し、最終的に RS の訂正能力
   `t = NROOTS/2 = 8` に張り付く。** 8 は「これ以上訂正できない」上限であり、
   同時に**「RS が見ているのは純粋なノイズ」**のsignature。
   散発的 bit error ではない。
2. 失敗理由はほぼ 100% `Fail::RootCountMismatch`
   （Chien 検索の根数が BM の次数と不一致）= **RS 復号器は健全**、
   入力が構造的に壊れている。`Miscorrected` / `ZeroDenominator` は 0。
3. **`soft`（Viterbi 入力の自信度）は 0.72 → 0.79 とむしろ改善**。
   `h_avg` も 419 → 403 で安定。pilot 位相 `m4` は 461 サンプル中
   **不一致 0 件**。depunc 位相も全ブロック正常。
4. `EQ data` の `|H|^2` **max が 188 → 5155 に跳ね上がる**
   （mean は 1.36 → 1.55 しか変わらない）= **局所的な等化の発散**が
   ある。まず 1 キャリアが飛び出し、それが soft の飽和（±8 クランプ）を
   経由してibarbitrary なビット腐敗を生む。

**結論（未確定）**: 復調が壊れるのは **等化器より下流**、
つまり demap → 周波数/時間デインターリーブ → depuncture → Viterbi →
byte 整列 → RS のどこかで注入されている。ただし soft（Viterbi 直前）が
健全なので、**Viterbi 自体の劣化ではなく、その前後の整列/遅延線の問題**が
最有力。候補:
- `ByteDeinterleaver`（固定遅延線なので drift しないが、**入力ビット数が
  1 個でもずれると恒久的にずれる**）
- 時間デインターリーブの遅延深度
- PRBS リセット周期（`ISDBT_RPERIOD`）— ただし §3 #14 で「全期間不変」と
  記録されており再検証が要る

次の手: Viterbi **入力**と**出力**のビットを 1 ブロック単位で突き合わせ、
どちらの段階で「まだ正しい、バイト列が壊れている」かを決める。

## 5. 未完の実験

### 5.1 強制再ロック（`ISDBT_RELOCK=N`）— 決定的なテスト

`lk` と `Pipe` を丸ごと作り直す完全再ロック。`Pipe::resync()`（部分リセット）が
悪化したのに対し、境界の基準（`cur` 付近）も取り直すため累積ドリフトが
ゼロから解け直される。

**実測結果（2026-09-27）: drop 7.8%（499 ブロック中 39）、改善せず悪化。**

ただし**この実験は設計に欠陥があり、仮説の判定には使えない**。

```
[relock] #1 cur=2303817
[relock] #2 cur=2303793
[relock] #3 cur=2303792
総blk=499 drop=39  → 7.8%
```

原因: 再ロック時の巻き戻し量が進行量に対して半分になっている。

```rust
let back = (rl / 2 * lk.sym).min(self.cur);   // 2000 × 1152 = 2,304,000 サンプル
self.cur -= back;
```

`rl=4000` シンボル = 4,608,000 サンプル進むが、巻き戻しが 2,304,000 サンプル。
結果として `cur` が 2,303,8xx に固定され、区間を半分しか前進しないまま
再ロックを繰り返す。53840 ブロック中 499 ブロックしか処理していない。

**測定しているのは「再ロックのオーバーヘッド」であって「内部状態の累積」ではない。**
しかも 7.8% > 対照 0.2% と悪化しており、理由は `Pipe::resync()` と同じ
（warm-up 領域と RS アセンブラ／TS 連続性を壊す）と整合する。

### 5.1b 巻き戻し 0 での再試行 — **実験として成立しない**

```rust
self.locked = None;
self.need_init = (LOCK_SYMS + 8) * 1280 + 60_000;   // 約 660 万サンプル ≈ 50 MB
```

実測結果:
```
ロック→ライブ復調開始
[relock] #1 cur=4607817
[relock] #2 cur=4607797
[relock] #3 cur=4607793
（`総blk` の行が一度も出ない = ブロック 0）
```

**再ロックは成立しない実験である。** 理由:

1. 再ロックごとに TMCC 探索用の warm-up 660 万サンプル（≈ 50 MB）が必要
2. その間 `syms_since_reacq` が増えないため次の再ロック条件に到達しない
3. 386 MB で 78 回の再ロック × TMCC 探索 = 240 秒でタイムアウト、
   ブロックが 1 つも出力されない
4. warm-up 50 MB と再ロック間隔 50 MB が同規模なので、
   **区間が原理的に前進しない**

巻き戻しを 0 に修正したが改善せず、上記 1〜4 が原因。
`ISDBT_RELOCK` は診断用として残すが、この仮説の検証には使えない。
「内部状態の累積か」を判定するには、warm-up を再利用可能な設計
（ロック済みパラメータを保持したまま等化器/Viterbi 状態だけ初期化）に
変える必要がある。

### 5.2 degraded クラスタリング（paste 23 の提案）

1 TSD = 204 バイトあたりの degraded 数をヒストグラム化し、
「0-7 個（訂正可能域）」と「8 個以上（訂正不能域、RS の t=8 閾値）」の
占比推移を測る。平均が動かないまま裾だけ太るなら、
単一連続量のドリフトではなく**バースト性（相関構造）自身の変化**が原因。

**初回計測は設計ミスで無効**: bin 幅を 256 にしたが 1 TSD あたりの degraded 数は
最大 204 のため全サンプルが bin 0 に入った。bin 幅を 1/4 刻みに修正して再計測が必要。

## 6. 診断コードの状態

すべて **既定無効**（環境変数 opt-in）。`cargo test -p isdbt-dsp` は 61 passed。

| 環境変数 | 内容 |
|---|---|
| `ISDBT_DEBUG=1` | `[dbg]` / `[chan]` / `[sat]` / `[vit]` / `[hist]` 出力 |
| `ISDBT_RESETBLK=N` | N ブロックごとに Pipe をリセット（**悪化するので使わない**） |
| `ISDBT_REACQ=0` | 再取得を無効化（曲線は変わらない） |
| `ISDBT_RELOCK=N` | N シンボルごとに完全再ロック（**未完**） |
| `ISDBT_DCTRACK=x` | DC 追従率（0=追従しない。効果なし確認済み） |
| `ISDBT_SPTRACK=1` | SP タイミングの fractional feedback（実 IQ で 100% 失敗） |
| `ISDBT_DROPPOS=1` | 256 bin の drop 位置ヒストグラム |
| `ISDBT_HIST=1` | TSD あたり degraded 数のヒストグラム（**要修正**） |
| `ISDBT_COMPACT=N` | buf の drain 境界長（0 で無効化） |
| `ISDBT_MAXSYMS=N` | 1 回の feed/pump で処理する最大シンボル数（0 で無効化） |
